# personal-website-knowledge

Static VitePress site for knowledge.irfanmim.com, authored in Obsidian. Independent of the
sibling repos `personal-website-fe` / `personal-website-be` (never edit those from here).

## Layout
- `vault/` is the Obsidian vault (content only). Open only this folder in Obsidian.
- `scripts/build-content.mjs` copies `publish: true` notes from `vault/` into the gitignored
  `.content/`, which is VitePress's `srcDir`. Unpublished notes never reach VitePress.
- `pages/` (home page) and `public/` (`.htaccess`, `robots.txt`) are copied into `.content/` by the same script.
- `.vitepress/` holds config and the theme.

## How the content flows
- Pipeline output in `.content/`: published entries (`<category>/<sub-path>/<slug>.md`), a generated
  `<category>/index.md` per category, and `_data/sidebar.json` (imported by `.vitepress/config.mts`;
  changing it restarts the dev server, which is how new notes reach the sidebar).
- Each entry gets its H1 (from `title`) followed by `<EntryMeta />` (badge, category, tags, dates) injected.
- Dates: front matter wins, else git history, else file mtime (the Docker container has no git, so it uses mtime).
- `categories.json` holds category labels, descriptions and display order; unknown folders fall back to title case.
- Theme (`.vitepress/theme/`) extends the default theme; tokens in `styles/tokens.css` come from
  `personal-website-fe/src/App.vue`. Entry data for home/category lists comes from
  `.vitepress/data/entries.data.js`. UI mockup: `mock/site-core.html`.

## Obsidian syntax (handled in `scripts/lib/`)
- `[[Name]]`, `[[Name|text]]`, `[[Name#Heading]]`, `[[folder/name]]` resolve by filename, then `aliases:`.
  Unpublished, draft or missing targets render as plain text (missing/ambiguous also log a warning).
  Code blocks and inline code are never rewritten.
- `![[img.png]]` / `![[img.png|300]]`: image found by filename anywhere in the vault, copied to
  `.content/attachments/` and referenced relatively so Vite hashes it (small SVG/PNG may be inlined).
- Callouts (`> [!tip] Title`, `[!note]-` foldable) via `.vitepress/plugins/callouts.js`
  (VitePress's built-in GFM alerts are turned off).
- Backlinks ("Linked from") are written into each target's front matter from published notes only.
- Renames: add `redirect_from: [/old-category/old-slug]` to the note (`aliases:` is only for link names).
  `slugs.json` lists every URL ever published; the build warns if one disappears without a redirect.
  `npm run dev` / `npm run slugs` update it, so commit it with your content. CI never edits it.

## Search, tags, SEO, images
- Search: VitePress local search over `.content/` only; generated listing pages (home, category, tag)
  set `search: false`. Tags: `tags/index.md` and `tags/<slug>.md` are generated by the pipeline
  (`.vitepress/tag-slug.js` is shared by pipeline and theme; `tags` is a reserved category name).
- SEO: `transformHead` in `.vitepress/config.mts` adds canonical, Open Graph, Twitter and Article JSON-LD;
  sitemap `lastmod` comes from each entry's `updated`. Default share image: `public/og-default.png`
  (regenerate with `npm run og`; needs a system font, see `scripts/make-og.mjs`).
- Raster images wider than 1600px are downscaled during the content build (`sharp`, optional at runtime).
- Setup/deploy/Obsidian Git instructions live in `README.md`.

## Commands
- Run `docker compose up -d --build` from `../personal-website-be` (the `knowledge` service there,
  override the path with `$KNOWLEDGE_PATH`) -> http://localhost:5174, hot reload, no local Node needed
- Or `npm install` then `npm run dev` (syncs vault -> `.content/`, watches, hot reloads)
- `npm run build` -> `.vitepress/dist/`; `npm run preview`
- No tests or linting configured.

## Rules
- The repo is PUBLIC. Unpublished notes go in `vault/_drafts/` (gitignored) and must never be committed.
- Folders `.x`, `_x` and `attachments` inside `vault/` are skipped by the pipeline.
- Deploy: push to `main` runs `.github/workflows/deploy.yml` (rsync over SSH, `--delete`).
  Secrets: `SSH_PRIVATE_KEY`, `SSH_HOST`, `SSH_PORT`, `SSH_USER`, `SSH_PATH`.
- Content commits use the `content:` prefix; code commits do not.
